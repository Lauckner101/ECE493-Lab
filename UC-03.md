# UC-03: Change User Password

## Use Case (Cockburn Style)

**Goal in Context**  
Allow a logged-in user to change their account password in order to maintain account security.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Registered User

**Secondary Actors**  
Authentication Service (internal)

**Trigger**  
User selects the “Change Password” option from account settings.

### Success End Condition
- The user’s password is successfully updated in the system.

### Failed End Condition
- The user’s password remains unchanged.

### Preconditions
- The user is registered in the CMS.
- The user is currently logged into the CMS.
- The CMS web application is available.

### Main Success Scenario
1. The user navigates to account settings.
2. The user selects the **Change Password** option.
3. The system displays the change password form.
4. The user enters the current password.
5. The user enters a new password and confirms it.
6. The user submits the password change request.
7. The system verifies the current password.
8. The system validates the new password against security requirements.
9. The system updates the user’s password.
10. The system confirms the password change to the user.

### Extensions
- **7a**: The current password is incorrect.  
  - The system displays an error message and prompts re-entry.
- **8a**: The new password does not meet security requirements.  
  - The system displays password rules and requests a valid password.
- **5a**: The new password and confirmation do not match.  
  - The system displays a mismatch error message.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
A registered user who is logged into the Conference Management System decides to update their password. The user navigates to the account settings area and selects the **Change Password** option. The system displays a form requesting the current password, a new password, and confirmation of the new password. After entering valid information, the user submits the request. The system verifies the current password, validates the new password, updates the stored password, and confirms the successful change.

### Alternative Scenario: Incorrect Current Password
If the user enters an incorrect current password, the system detects the mismatch during verification. The system displays an error message indicating that the current password is invalid and prompts the user to re-enter the correct password.

### Alternative Scenario: New Password Does Not Meet Requirements
If the user enters a new password that does not meet the system’s security requirements, the system rejects the request. The system displays an explanation of the password rules and prompts the user to enter a valid new password.

### Alternative Scenario: Password Confirmation Mismatch
If the new password and confirmation password do not match, the system detects the mismatch and displays an error message. The user is prompted to re-enter the new password and confirmation correctly.

## Acceptance Test Suite — UC-03

### AT-UC03-001 — Successful Password Change
**Preconditions:** User is logged in; current password is valid.  
**Steps:**  
1. Open change password page  
2. Enter correct current password  
3. Enter valid new password and confirmation  
4. Submit request  

**Expected Results:**  
- Password is updated  
- Confirmation message displayed  

---

### AT-UC03-002 — Incorrect Current Password
**Preconditions:** User is logged in.  
**Steps:**  
1. Enter incorrect current password  
2. Enter valid new password  
3. Submit request  

**Expected Results:**  
- Error message displayed  
- Password unchanged  

---

### AT-UC03-003 — Weak New Password
**Preconditions:** User is logged in.  
**Steps:**  
1. Enter correct current password  
2. Enter weak new password  
3. Submit request  

**Expected Results:**  
- Password validation error displayed  
- Password unchanged  

---

### AT-UC03-004 — Password Confirmation Mismatch
**Preconditions:** User is logged in.  
**Steps:**  
1. Enter correct current password  
2. Enter mismatched new password and confirmation  
3. Submit request  

**Expected Results:**  
- Mismatch error displayed  
- Password unchanged  

---

### AT-UC03-005 — Missing Required Fields
**Preconditions:** User on change password form.  
**Steps:**  
1. Leave one or more fields blank  
2. Submit request  

**Expected Results:**  
- Missing fields highlighted  
- Password unchanged  

---

### AT-UC03-006 — Old Password No Longer Valid After Change
**Preconditions:** Successful password change completed.  
**Steps:**  
1. Log out  
2. Attempt login with old password  
3. Attempt login with new password  

**Expected Results:**  
- Login with old password fails  
- Login with new password succeeds  

---

### AT-UC03-007 — Prevent Reusing Same Password
**Preconditions:** User is logged in.  
**Steps:**  
1. Enter current password as new password  
2. Submit request  

**Expected Results:**  
- Password reuse rejected  
- Error message displayed
