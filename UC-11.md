# UC-11: Edit Conference Schedule

## Use Case (Cockburn Style)

**Goal in Context**  
Allow an editor to modify an existing conference schedule to resolve conflicts or make adjustments.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Editor

**Secondary Actors**  
Database System

**Trigger**  
Editor selects the **Edit Schedule** option for the current conference schedule.

### Success End Condition
- The updated conference schedule is successfully saved and becomes the current schedule.

### Failed End Condition
- The schedule remains unchanged.

### Preconditions
- The editor is registered and logged into the CMS.
- A conference schedule already exists.
- The CMS web application is available.

### Main Success Scenario
1. The editor navigates to the schedule management page.
2. The editor selects **Edit Schedule**.
3. The system displays the current schedule in editable form.
4. The editor modifies room and/or time assignments.
5. The editor submits the updated schedule.
6. The system validates the updated schedule for conflicts.
7. The system stores the updated schedule.
8. The system confirms the successful update to the editor.

### Extensions
- **6a**: The updated schedule contains conflicts.  
  - The system displays conflict errors and blocks saving.
- **5a**: No changes are made to the schedule.  
  - The system informs the editor that no updates were detected.
- **7a**: A system error occurs while saving the schedule.  
  - The system notifies the editor that the schedule could not be saved.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
An editor logs into the Conference Management System and navigates to the schedule management area. The editor selects **Edit Schedule**, and the system displays the current conference schedule in an editable format. The editor makes valid changes to room or time slot assignments and submits the updated schedule. The system validates the changes, saves the updated schedule, and confirms the successful update.

### Alternative Scenario: Schedule Conflicts Detected
If the editor makes changes that result in conflicts, such as assigning two papers to the same room at the same time, the system detects the conflict during validation. The system displays an error message and prevents the schedule from being saved until the conflict is resolved.

### Alternative Scenario: No Changes Made
If the editor opens the schedule editor but submits the schedule without making any changes, the system detects that no updates were made. The system informs the editor that there is nothing to save and leaves the schedule unchanged.

### Alternative Scenario: System Error During Save
If a system error occurs while saving the updated schedule, the system informs the editor that the schedule could not be saved. The current schedule remains unchanged, and the editor may retry later.

## Acceptance Test Suite — UC-11

### AT-UC11-001 — Edit Schedule Successfully
**Preconditions:** Schedule exists; editor logged in.  
**Steps:**  
1. Open schedule editor  
2. Make valid changes  
3. Save schedule  

**Expected Results:**  
- Schedule updated  
- Confirmation displayed  

---

### AT-UC11-002 — Conflict Detected During Edit
**Preconditions:** Schedule exists.  
**Steps:**  
1. Create conflicting assignments  
2. Attempt to save  

**Expected Results:**  
- Conflict error displayed  
- Schedule not saved  

---

### AT-UC11-003 — No Changes Made
**Preconditions:** Schedule exists.  
**Steps:**  
1. Open editor  
2. Save without changes  

**Expected Results:**  
- Informational message displayed  
- Schedule unchanged  

---

### AT-UC11-004 — System Error While Saving
**Preconditions:** Backend failure simulated.  
**Steps:**  
1. Make valid changes  
2. Save schedule  

**Expected Results:**  
- Error message displayed  
- Schedule unchanged  

---

### AT-UC11-005 — Persistence of Edited Schedule
**Preconditions:** Schedule updated successfully.  
**Steps:**  
1. Refresh or reopen schedule  

**Expected Results:**  
- Updated schedule persists  

---

### AT-UC11-006 — Replace Previous Schedule Version
**Preconditions:** Schedule already edited once.  
**Steps:**  
1. Edit schedule again  
2. Save changes  

**Expected Results:**  
- Latest version becomes current schedule  

---

### AT-UC11-007 — Unauthorized User Cannot Edit Schedule
**Preconditions:** Non-editor user logged in.  
**Steps:**  
1. Attempt to access edit schedule  

**Expected Results:**  
- Access denied
