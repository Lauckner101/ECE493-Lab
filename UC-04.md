# UC-04: Submit Paper Manuscript

## Use Case (Cockburn Style)

**Goal in Context**  
Allow an author to submit a paper manuscript for consideration at the conference.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Author

**Secondary Actors**  
File Storage System

**Trigger**  
Author selects the “Submit Paper” option from their home page.

### Success End Condition
- The paper manuscript and metadata are successfully stored.
- The paper is marked as submitted and available for review.

### Failed End Condition
- The paper is not submitted and is not available for review.

### Preconditions
- The author is registered in the CMS.
- The author is logged into the CMS.
- The CMS web application is available.

### Main Success Scenario
1. The author selects the **Submit Paper** option.
2. The system displays the paper submission form.
3. The author enters all required paper metadata.
4. The author uploads the manuscript file.
5. The author submits the paper.
6. The system validates the metadata and manuscript file.
7. The system stores the paper and manuscript.
8. The system confirms successful submission to the author.

### Extensions
- **6a**: Required metadata fields are missing.  
  - The system highlights missing fields and prompts completion.
- **7a**: The uploaded file format is invalid.  
  - The system displays supported file format requirements.
- **7b**: The uploaded file exceeds the maximum allowed size.  
  - The system displays a file size error message.
- **4a**: The author chooses to save the submission as a draft.  
  - The system saves the current information without submitting the paper.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
An author logged into the Conference Management System decides to submit a paper for the conference. The author selects **Submit Paper** and is presented with a submission form. The author enters all required metadata, uploads a properly formatted manuscript file, and submits the form. The system validates the input, stores the manuscript and metadata, and confirms that the paper has been successfully submitted.

### Alternative Scenario: Missing Required Fields
If the author submits the form without completing all required metadata fields, the system detects the omission. The system highlights the missing fields and informs the author that all required information must be provided before submission can proceed.

### Alternative Scenario: Invalid File Format
If the author uploads a manuscript file in an unsupported format, the system rejects the submission and displays a message listing the accepted file formats.

### Alternative Scenario: File Size Exceeds Limit
If the uploaded manuscript file exceeds the maximum allowed file size, the system displays an error message indicating the file size restriction and prevents submission.

### Alternative Scenario: Save Submission as Draft
If the author chooses not to submit the paper immediately, the author selects the **Save** option. The system saves the entered information as a draft, allowing the author to return later and complete the submission.

## Acceptance Test Suite — UC-04

### AT-UC04-001 — Successful Paper Submission
**Preconditions:** Author is logged in; valid manuscript file available.  
**Steps:**  
1. Open submission form  
2. Enter valid metadata  
3. Upload valid manuscript  
4. Submit paper  

**Expected Results:**  
- Paper is stored  
- Confirmation displayed  
- Paper marked as submitted  

---

### AT-UC04-002 — Missing Required Metadata
**Preconditions:** Author on submission form.  
**Steps:**  
1. Leave one or more required fields blank  
2. Upload valid manuscript  
3. Submit paper  

**Expected Results:**  
- Missing fields highlighted  
- Submission blocked  

---

### AT-UC04-003 — Invalid File Format
**Preconditions:** Author on submission form.  
**Steps:**  
1. Enter valid metadata  
2. Upload unsupported file type  
3. Submit paper  

**Expected Results:**  
- File format error displayed  
- Submission blocked  

---

### AT-UC04-004 — File Size Exceeds Limit
**Preconditions:** Author on submission form.  
**Steps:**  
1. Enter valid metadata  
2. Upload oversized file  
3. Submit paper  

**Expected Results:**  
- File size error displayed  
- Submission blocked  

---

### AT-UC04-005 — Save Draft Instead of Submit
**Preconditions:** Author on submission form.  
**Steps:**  
1. Enter partial metadata  
2. Click **Save**  

**Expected Results:**  
- Draft saved  
- Paper not marked as submitted  

---

### AT-UC04-006 — Submit Saved Draft
**Preconditions:** Draft exists.  
**Steps:**  
1. Open saved draft  
2. Complete metadata and upload file  
3. Submit paper  

**Expected Results:**  
- Draft converted to submitted paper  
- Confirmation displayed  

---

### AT-UC04-007 — Prevent Duplicate Submission
**Preconditions:** Author submits paper.

1. Double-click submit button  

**Expected Results:**
