# UC-07: Accept or Reject Review Invitation

## Use Case (Cockburn Style)

**Goal in Context**  
Allow a referee to accept or reject a review invitation so that referee assignments can be confirmed.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Referee (Reviewer)

**Secondary Actors**  
Editor, Email Notification System

**Trigger**  
Referee opens a review invitation and selects either Accept or Reject.

### Success End Condition
- The referee’s response is recorded.
- If accepted, the paper is assigned to the referee.

### Failed End Condition
- The referee’s response is not recorded.
- The paper remains without a confirmed referee assignment.

### Preconditions
- The referee is registered in the CMS.
- A valid review invitation exists.
- The CMS web application is available.

### Main Success Scenario
1. The referee opens the review invitation.
2. The system displays paper information and response options.
3. The referee selects **Accept**.
4. The system verifies referee workload limits.
5. The system assigns the paper to the referee.
6. The system updates the paper’s referee count.
7. The system confirms acceptance to the referee.
8. The system notifies the editor of the acceptance.

### Extensions
- **3a**: The referee selects **Reject**.  
  - The system records the rejection and notifies the editor.
- **4a**: The paper already has three assigned referees.  
  - The system blocks acceptance and notifies the referee and editor.
- **4b**: The referee has reached the maximum workload.  
  - The system blocks acceptance and notifies the editor.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
A referee receives a review invitation and opens it. The system displays the paper details along with options to accept or reject the invitation. The referee selects **Accept**. The system verifies that the referee has not exceeded workload limits and that the paper does not already have three referees. The system assigns the paper to the referee and notifies the editor of the successful acceptance.

### Alternative Scenario: Referee Rejects Invitation
If the referee selects **Reject**, the system records the rejection and does not assign the paper to the referee. The system notifies the editor so that another referee can be assigned.

### Alternative Scenario: Paper Already Has Three Referees
If the referee attempts to accept the invitation but the paper already has three assigned referees, the system blocks the assignment and informs both the referee and the editor.

### Alternative Scenario: Referee Workload Limit Reached
If the referee has already reached the maximum number of assigned papers, the system prevents acceptance of the invitation and notifies the editor of the workload constraint.

## Acceptance Test Suite — UC-07

### AT-UC07-001 — Accept Invitation Successfully
**Preconditions:** Valid invitation exists; referee workload < limit; paper has fewer than three referees.  
**Steps:**  
1. Open invitation  
2. Select **Accept**  

**Expected Results:**  
- Invitation accepted  
- Paper assigned to referee  
- Editor notified  

---

### AT-UC07-002 — Reject Invitation
**Preconditions:** Valid invitation exists.  
**Steps:**  
1. Open invitation  
2. Select **Reject**  

**Expected Results:**  
- Rejection recorded  
- Paper not assigned  
- Editor notified  

---

### AT-UC07-003 — Paper Already Has Three Referees
**Preconditions:** Paper already has three referees assigned.  
**Steps:**  
1. Attempt to accept invitation  

**Expected Results:**  
- Acceptance blocked  
- Error message displayed  
- Editor notified  

---

### AT-UC07-004 — Referee Workload Limit Exceeded
**Preconditions:** Referee has reached maximum workload.  
**Steps:**  
1. Attempt to accept invitation  

**Expected Results:**  
- Acceptance blocked  
- Workload error displayed  
- Editor notified  

---

### AT-UC07-005 — Invalid or Expired Invitation
**Preconditions:** Invitation token invalid or expired.  
**Steps:**  
1. Open invitation link  

**Expected Results:**  
- Error message displayed  
- No response recorded  

---

### AT-UC07-006 — Prevent Duplicate Acceptance
**Preconditions:** Invitation already accepted.  
**Steps:**  
1. Attempt to accept invitation again  

**Expected Results:**  
- No duplicate assignment  
- Informational message displayed  

---

### AT-UC07-007 — Paper Visible in Referee Account After Acceptance
**Preconditions:** Invitation accepted successfully.  
**Steps:**  
1. Log into CMS  
2. View assigned papers  

**Expected Results:**  
- Paper appears in referee’s assigned list
