# UC-01: Register User Account

## Use Case (Cockburn Style)

**Goal in Context**  
Allow a guest to create a user account in order to access Conference Management System features.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Guest

**Secondary Actors**  
Email Notification System

**Trigger**  
Guest selects the “Register” option on the CMS homepage.

### Success End Condition
- A new user account is successfully created and stored.
- The user is redirected to the login page.

### Failed End Condition
- No user account is created.

### Preconditions
- The guest is not logged into the CMS.
- The CMS web application is available.

### Main Success Scenario
1. The guest selects the **Register** option.
2. The system displays the user registration form.
3. The guest enters all required registration information.
4. The guest submits the registration form.
5. The system validates the email address and password.
6. The system stores the new user account information.
7. The system confirms successful registration and redirects the user to the login page.

### Extensions
- **5a**: The email address is already registered.  
  - The system displays an error message and prompts the guest to enter a different email.
- **5b**: The password does not meet security requirements.  
  - The system displays password rules and prompts the guest to enter a valid password.
- **3a**: Required fields are missing.  
  - The system highlights missing fields and requests completion.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
A guest visits the Conference Management System and decides to create an account. The guest selects the **Register** option and is presented with a registration form. After entering valid personal information, including a unique email address and a compliant password, the guest submits the form. The system validates the input, creates a new user account, and redirects the guest to the login page.

### Alternative Scenario: Email Address Already Registered
If the guest enters an email address that already exists in the system, the system detects the duplication during validation. The system displays an error message indicating that the email address is already in use and prompts the guest to provide a different email address.

### Alternative Scenario: Invalid Password
If the guest provides a password that does not meet the system’s security requirements, the system rejects the submission and displays an explanation of the password rules. The guest is prompted to enter a valid password before resubmitting.

### Alternative Scenario: Missing Required Fields
If the guest submits the form without completing all required fields, the system highlights the missing fields and informs the guest that all required information must be provided before registration can proceed.

## Acceptance Test Suite — UC-01

### AT-UC01-001 — Successful Registration
**Preconditions:** Guest is not logged in; email does not exist in system.  
**Steps:**  
1. Open registration page  
2. Enter valid name, email, and password  
3. Submit form  

**Expected Results:**  
- Account is created  
- User is redirected to login page  

---

### AT-UC01-002 — Duplicate Email Address
**Preconditions:** Email already exists in database.  
**Steps:**  
1. Enter existing email  
2. Enter valid password  
3. Submit form  

**Expected Results:**  
- Error message displayed  
- No account created  

---

### AT-UC01-003 — Invalid Password
**Preconditions:** Email does not exist.  
**Steps:**  
1. Enter valid email  
2. Enter weak password  
3. Submit form  

**Expected Results:**  
- Password error displayed  
- No account created  

---

### AT-UC01-004 — Missing Required Fields
**Preconditions:** Guest on registration form.  
**Steps:**  
1. Leave one or more required fields blank  
2. Submit form  

**Expected Results:**  
- Missing fields highlighted  
- Registration blocked  

---

### AT-UC01-005 — Invalid Email Format
**Steps:**  
1. Enter malformed email  
2. Submit form  

**Expected Results:**  
- Email validation error  
- No account created  

---

### AT-UC01-006 — Email Case Insensitivity
**Preconditions:** Email exists in lowercase.  
**Steps:**  
1. Enter same email with different casing  
2. Submit form  

**Expected Results:**  
- Registration blocked  
- Duplicate detected  

---

### AT-UC01-007 — Login After Registration
**Preconditions:** Successful registration completed.  
**Steps:**  
1. Navigate to login page  
2. Enter newly registered credentials  

**Expected Results:**  
- Login succeeds  
- User redirected to home page
