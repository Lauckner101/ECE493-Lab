# UC-08: Review Assigned Paper

## Use Case (Cockburn Style)

**Goal in Context**  
Allow a referee to review an assigned paper and submit a completed review.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Referee (Reviewer)

**Secondary Actors**  
Editor, Database System

**Trigger**  
Referee selects an assigned paper to review.

### Success End Condition
- The referee’s review is successfully submitted and stored.
- The editor is notified that a review has been completed.

### Failed End Condition
- The review is not submitted or stored.

### Preconditions
- The referee is registered and logged into the CMS.
- The referee has accepted a review invitation for the paper.
- The paper is available for review.

### Main Success Scenario
1. The referee logs into the CMS.
2. The referee navigates to their list of assigned papers.
3. The referee selects a paper to review.
4. The system displays the paper details and review form.
5. The referee completes all required review fields.
6. The referee submits the review.
7. The system validates the review input.
8. The system stores the review.
9. The system confirms submission to the referee.
10. The system notifies the editor of the completed review.

### Extensions
- **5a**: Required review fields are missing.  
  - The system highlights missing fields and blocks submission.
- **7a**: Review contains invalid data.  
  - The system displays a validation error message.
- **8a**: A system error occurs while saving the review.  
  - The system notifies the referee that the review could not be saved.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
A referee logs into the Conference Management System and navigates to their assigned papers. The referee selects a paper to review and is presented with the paper details and a review form. After completing all required fields with valid input, the referee submits the review. The system validates the information, stores the review, confirms submission to the referee, and notifies the editor that the review has been completed.

### Alternative Scenario: Missing Required Review Fields
If the referee attempts to submit the review without completing all required fields, the system detects the missing information. The system highlights the missing fields and informs the referee that all required fields must be completed before submission can proceed.

### Alternative Scenario: Invalid Review Data
If the referee enters invalid data into the review form, such as unsupported characters or out-of-range values, the system rejects the submission and displays an error message explaining the validation issue.

### Alternative Scenario: System Error During Review Submission
If a system error occurs while saving the review, the system notifies the referee that the submission failed. The review is not stored, and the referee is allowed to retry submission after the issue is resolved.

## Acceptance Test Suite — UC-08

### AT-UC08-001 — Submit Review Successfully
**Preconditions:** Referee logged in; paper assigned and not yet reviewed.  
**Steps:**  
1. Open assigned paper  
2. Complete review form with valid data  
3. Submit review  

**Expected Results:**  
- Review saved  
- Confirmation displayed  
- Editor notified  

---

### AT-UC08-002 — Missing Required Review Fields
**Preconditions:** Referee on review form.  
**Steps:**  
1. Leave one or more required fields blank  
2. Submit review  

**Expected Results:**  
- Missing fields highlighted  
- Submission blocked  

---

### AT-UC08-003 — Invalid Review Data
**Preconditions:** Referee on review form.  
**Steps:**  
1. Enter invalid data  
2. Submit review  

**Expected Results:**  
- Validation error displayed  
- Review not saved  

---

### AT-UC08-004 — System Error During Review Submission
**Preconditions:** Backend failure simulated.  
**Steps:**  
1. Complete review form  
2. Submit review  

**Expected Results:**  
- Error message displayed  
- Review not saved  

---

### AT-UC08-005 — Prevent Duplicate Review Submission
**Preconditions:** Review already submitted.  
**Steps:**  
1. Attempt to resubmit review  

**Expected Results:**  
- Duplicate submission blocked  

---

### AT-UC08-006 — Review Visible to Editor

- Review visible to editor  

---

### AT-UC08-007 — Retry Review Submission After Failure
**Preconditions:** Previous submission failed.  
**Steps:**  
1. Retry submission
