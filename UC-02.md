# UC-02: Log In User

## Use Case (Cockburn Style)

**Goal in Context**  
Allow a registered user to authenticate and gain access to Conference Management System features.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Registered User

**Secondary Actors**  
Authentication Service (internal)

**Trigger**  
User selects the “Log In” option on the CMS homepage.

### Success End Condition
- The user is authenticated and redirected to their home page with an active session.

### Failed End Condition
- The user is not authenticated and remains on the login page.

### Preconditions
- The user is registered in the CMS.
- The CMS web application is online and accessible.

### Main Success Scenario
1. The user selects the **Log In** option.
2. The system displays the login form.
3. The user enters their username and password.
4. The user submits the login form.
5. The system validates the credentials against stored account data.
6. The system creates an authenticated user session.
7. The system redirects the user to their home page.

### Extensions
- **5a**: The username does not exist.  
  - The system displays an error message indicating invalid credentials.
- **5b**: The password is incorrect.  
  - The system displays an error message indicating invalid credentials.
- **3a**: Required fields are missing.  
  - The system highlights missing fields and requests completion.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
A registered user navigates to the Conference Management System and selects the **Log In** option. The system presents a login form requesting a username and password. The user enters valid credentials and submits the form. The system successfully authenticates the user, creates an active session, and redirects the user to their personalized home page.

### Alternative Scenario: Username Does Not Exist
If the user enters a username that is not registered in the system, the system fails to authenticate the request. An error message is displayed indicating that the login credentials are invalid, and the user is prompted to try again.

### Alternative Scenario: Incorrect Password
If the user enters a valid username but an incorrect password, the system rejects the authentication attempt. The system displays an error message indicating invalid credentials and allows the user to retry.

### Alternative Scenario: Missing Required Fields
If the user submits the login form without entering a username or password, the system detects the missing input. The system highlights the missing fields and informs the user that all required information must be provided before logging in.

## Acceptance Test Suite — UC-02

### AT-UC02-001 — Successful Login
**Preconditions:** User account exists; user is not logged in.  
**Steps:**  
1. Open login page  
2. Enter valid username and password  
3. Submit login form  

**Expected Results:**  
- User is authenticated  
- User redirected to home page  
- Active session is created  

---

### AT-UC02-002 — Username Does Not Exist
**Preconditions:** Username is not registered in the system.  
**Steps:**  
1. Enter non-existent username  
2. Enter any password  
3. Submit login form  

**Expected Results:**  
- Login rejected  
- Error message displayed  
- No session created  

---

### AT-UC02-003 — Incorrect Password
**Preconditions:** Username exists; password is incorrect.  
**Steps:**  
1. Enter valid username  
2. Enter incorrect password  
3. Submit login form  

**Expected Results:**  
- Login rejected  
- Error message displayed  
- No session created  

---

### AT-UC02-004 — Missing Username or Password
**Preconditions:** User on login page.  
**Steps:**  
1. Leave username or password blank  
2. Submit login form  

**Expected Results:**  
- Missing fields highlighted  
- Login blocked  

---

### AT-UC02-005 — Session Persistence After Login
**Preconditions:** Successful login completed.  
**Steps:**  
1. Navigate to another protected page  
2. Refresh the page  

**Expected Results:**  
- User remains authenticated  
- Page remains accessible  

---

### AT-UC02-006 — Access Login Page While Already Logged In
**Preconditions:** User already logged in.  
**Steps:**  
1. Navigate to login page  

**Expected Results:**  
- User redirected to home page or informed they are already logged in  

---

### AT-UC02-007 — Case-Insensitive Username Matching
**Preconditions:** Username is stored in lowercase.  
**Steps:**  
1. Enter same username with different letter casing  
2. Enter correct password  
3. Submit login form  

**Expected Results:**  
- Login succeeds  
- User redirected to home page
