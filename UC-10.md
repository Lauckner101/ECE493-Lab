# UC-10: Generate Conference Schedule

## Use Case (Cockburn Style)

**Goal in Context**  
Allow an administrator to generate a conference schedule for accepted papers.

**Scope**  
Conference Management System (CMS)

**Level**  
User Goal

**Primary Actor**  
Administrator

**Secondary Actors**  
Scheduling Algorithm (Algorithm X), Database System

**Trigger**  
Administrator selects the **Generate Schedule** option.

### Success End Condition
- A valid conference schedule is generated and stored.
- The schedule is available for viewing.

### Failed End Condition
- No schedule is generated or saved.

### Preconditions
- The administrator is registered and logged into the CMS.
- At least one paper has been accepted.
- Rooms and time slots are defined.

### Main Success Scenario
1. The administrator navigates to schedule management.
2. The administrator selects **Generate Schedule**.
3. The system retrieves accepted papers, rooms, and time slots.
4. The system executes the scheduling algorithm.
5. The system generates a valid schedule.
6. The system stores the schedule.
7. The system displays the generated schedule in HTML format.

### Extensions
- **2a**: No accepted papers exist.  
  - The system blocks generation and informs the administrator.
- **4a**: Scheduling constraints cannot be satisfied.  
  - The system reports conflicts and does not save an invalid schedule.
- **6a**: A system error occurs while saving the schedule.  
  - The system notifies the administrator that the schedule could not be saved.

---

## Fully Dressed Scenario Narratives

### Main Success Scenario Narrative
An administrator logs into the Conference Management System and accesses the schedule management area. The administrator selects **Generate Schedule**. The system gathers all accepted papers along with available rooms and time slots, then runs the scheduling algorithm. A valid conference schedule is produced, saved in the system, and displayed to the administrator in HTML format.

### Alternative Scenario: No Accepted Papers
If the administrator attempts to generate a schedule when no papers have been accepted, the system blocks the request. The system displays a message indicating that a schedule cannot be generated without accepted papers.

### Alternative Scenario: Unsatisfiable Scheduling Constraints
If the scheduling algorithm determines that available rooms or time slots are insufficient to schedule all accepted papers, the system reports the conflict. The system does not save an invalid or partial schedule and prompts the administrator to adjust inputs.

### Alternative Scenario: System Error During Schedule Save
If a system error occurs while saving the generated schedule, the system informs the administrator that the schedule could not be saved. The generated schedule is not stored, and the administrator may retry later.
